Part B: Monitor Implementation Design & Pseudocode

SOLUTION STRATEGY:
C does not have native monitor objects, so we enforce the mutual exclusion 
boundary manually. We use a single global binary semaphore (initialized to 1) 
called `monitor_mutex`. Every monitor procedure must start with `MonEnter()` 
and end with `MonLeave()`. 

For condition variables (CVs), we maintain an array of 10 lists (using our A1 
list library) to track blocked threads, and an array of 10 semaphores 
(initialized to 0) to execute the blocking. 

WHY THIS IS CORRECT:
By guarding every monitor entry/exit with the `monitor_mutex`, we guarantee 
strict mutual exclusion; no two threads can execute monitor code simultaneously. 
When a thread calls `MonWait()`, it deliberately releases the `monitor_mutex` 
before blocking on the CV semaphore. This prevents deadlocks and allows another 
thread to enter the monitor. Crucially, upon waking, the signaled thread 
immediately blocks to re-acquire the `monitor_mutex`, ensuring that the mutual 
exclusion invariant is never violated during a context switch.

 Pseudocode

RttMonInit(numConds):
    RttAllocSem(&monitor_mutex, 1, RTTPRIORITY)
    for i = 0 to numConds - 1:
        cv_lists[i] = ListCreate()

RttMonEnter():
    RttP(monitor_mutex)

RttMonLeave():
    RttV(monitor_mutex)

RttMonWait(cv):
    private_sem = allocate new semaphore(0, RTTPRIORITY)
    ListAppend(cv_lists[cv], private_sem)
    
    RttMonLeave()       /* drop main lock */
    RttP(private_sem)   /* go to sleep */
    free(private_sem)
    
    RttMonEnter()       /* grab lock again after waking up */

RttMonSignal(cv):
    if ListCount(cv_lists[cv]) > 0:
        ListFirst(cv_lists[cv])
        popped_sem = ListRemove(cv_lists[cv])
        RttV(popped_sem) /* wake the specific thread */
